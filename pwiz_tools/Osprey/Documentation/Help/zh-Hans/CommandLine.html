Osprey 命令行用法

Osprey 是 MacCoss 实验室开发的以肽段为中心的 DIA 搜索工具。它读取 DIA mzML 文件和谱图库，并将经过 FDR 控制的结果写入 BiblioSpecLite（.blib）库，该库可直接导入 Skyline。它在 Windows 和 Linux 上作为独立的可执行文件运行。

有关流程概述、各阶段详情以及四个分布式 HPC 任务如何拆分与合并，请参见工作流程图：Osprey-workflow.html。下方的参数表由命令行声明生成，因此始终与构建版本一致；运行 Osprey --help 可查看相同内容的文本版本。

Osprey - 以肽段为中心的 DIA 分析

用法：osprey -i <file1.mzML> [file2.mzML ...] -l <library.tsv> -o <output.blib>

一般输入/输出
参数描述
-i, --input <file1.mzML ...>输入 mzML 文件
--input-list <list.txt>输入路径列表文件，每行一个（忽略 # 注释）。可替代很长的“-i”列表。
-l, --library <library.tsv|.blib>谱图库（.tsv，.blib）
-o, --output <output.blib>输出 blib 文件
--work-dir <dir>将中间文件和谱图缓存写入此处（使输入数据可以是只读的）；默认：输入旁
--output-dir <dir>中间文件的目录（覆盖“--work-dir”）
--cache-dir <dir>.spectra.bin 缓存的目录（覆盖“--work-dir”）
--report <report.tsv>将 TSV 报告写入文件
--export-library <library.blib>Write the spectral library given by --library to this path as a .blib file that Skyline and Osprey can read, and exit without searching
评分与耐受性
参数描述
--resolution <unit | hram | auto>分辨率模式（默认：auto）
--fragment-tolerance <value>碎片质荷比耐受性（默认：10）
--fragment-unit <ppm | mz>碎片耐受性单位（默认：ppm）
--no-prefilter禁用共洗脱信号预过滤
FDR 与蛋白质推断
参数描述
--run-fdr <threshold>运行水平 FDR 阈值（默认：0.01）
--experiment-fdr <threshold>实验水平 FDR 阈值（默认：0.01）
--reconciliation-compaction-fdr <threshold>为跨运行协调和第二轮保留第一轮肽段的肽段 q 值阈值（默认：0.01 =“--run-fdr”；可放宽，例如到 0.05，以扩大协调池）
--protein-fdr <threshold>蛋白质水平 FDR 阈值（可选）
--fdr-level <precursor | peptide | both>FDR 水平（默认：precursor）
--shared-peptides <all | razor | unique>共享肽段处理方式（默认：all）
--fdrbench <input.tsv>将与 FDRBench 兼容的输入 TSV 写入此路径。水平取自“--fdr-level”（peptide；precursor 和 both 输出母离子水平）。包含每个报告的目标，即实际写入输出的肽段，不论 q 值如何，并将原始 SVM 判别值作为“score”，以便 FDRBench 通过诱捕计数计算真实 FDR，而不会在 Osprey 的阈值处截断。
--fdrbench-per-run与“--fdrbench”一起使用：每个（母离子，运行）输出一行，使用运行水平 q 值（增加“run”列）。默认每个母离子输出一行，使用实验水平 q 值。
--fdrbench-pass <1 | 2 | both>与“--fdrbench”一起使用：要输出哪一轮 FDR。2（默认）= 写入 blib 的第二轮结果（即 Osprey 所报告内容的 FDR）。1 = 为第二轮筛选之前的完整第一轮池（每个已评分目标，不论 q 值），使用第一轮 q 值，与原始 Rust Osprey 的 FDRBench 输入一致（第二轮输出所依据的假设）。both = 在一次运行中同时输出两者，写入“--fdrbench”路径时使用 .pass1 / .pass2 文件名后缀。
诱饵
参数描述
--decoys-in-library信任谱图库中已有的诱饵，而不是生成反向诱饵。如果未识别到任何诱饵，则报错停止。
--decoy-pairing-manifest <manifest.tsv>FDRBench 5 列配对清单 (TSV)，与“--decoys-in-library”一起使用
--write-pin为外部工具写入 PIN 文件
Training Export
参数描述
--training-exportWrite <stem>.training.parquet per run: every target precursor at run q <= --training-export-max-q with the observed intensities of its full b/y ladder and per-ion interference evidence (for training CarafeSharp). Adding it to a finished run writes only the exports and re-scores nothing.
--training-export-max-q <q>With --training-export: the run precursor q-value a target must reach to be exported (default: --run-fdr)
--training-export-claimant-q <q>With --training-export: the run q-value at which another target counts as a claimant of a shared fragment peak (default: 0.01)
--training-export-xicsWith --training-export: also write each precursor's per-ion XIC matrix over its final peak boundaries
性能
参数描述
--parallel-files [<N>]同时评分的输入文件数（外层）。省略：每次一个（默认）。不带值：根据可用内存和核心数自动确定。<N>：不论内存和核心数，恰好为 N。与“--threads”不同。
--parallel-files-caching [<N>]Files --task SpectraCache caches concurrently, overriding --parallel-files for that stage only, in the same forms (a full run caches inside scoring, at its count). A vendor decode runs on one thread, so this can exceed the scoring count; mzML parses still run one at a time.
--parallel-files-scoring [<N>]Files scored concurrently (PerFileScoring), overriding --parallel-files for that stage only, in the same forms.
--parallel-files-rescoring [<N>]Files re-scored concurrently (PerFileRescoring, and the second-pass per-file phases), overriding --parallel-files for that stage only, in the same forms.
--threads <count>每个文件的主搜索线程数（内层；默认：所有核心），在“--parallel-files”同时运行的文件之间分配
分布式 / HPC
参数描述
--task <SpectraCache | PerFileScoring | FirstPassFDR | PerFileRescoring | SecondPassFDR | TrainingExport | ModelDiagnostics>HPC：只运行一个流程任务（一个节点 = 一个任务）。省略则运行完整流程。SpectraCache 准备 .spectra.bin 缓存；TrainingExport 写入“--training-export”parquet 文件（对已完成的运行仅写入缺失的文件）；ModelDiagnostics 仅为已完成的运行重新生成“--model-diagnostics”报告，不写入其他输出。
日志
参数描述
--timestamp在每行输出前加上 [yyyy/MM/dd HH:mm:ss]
--memstamp在每行输出前加上以 MB 为单位的托管内存和专用内存（与“--timestamp”配合使用，供 perfviz 读取）
--log-file <path>将所有输出写入此文件，而不是 stderr
--perf-stats输出脚本和性能工具读取的机器可解析 [COUNT], [TIMING], [BENCH], [STAGE-WALL], [PATH], [TRAIN] 行（默认关闭）
--verbose显示默认隐藏的更多详细信息（例如每折的 Percolator 迭代）
诊断与信息
参数描述
-d, --diagnostics写入开发人员诊断转储文件，用于与 Rust 实现进行比较
--model-diagnostics写入独立的交互式 HTML 报告，内容包括训练好的评分模型、FDR 校准，以及单峰多 ID 重复分配
-h, --help显示此帮助信息（[ascii|unicode|sections|html|<Section>]）
-v, --version显示版本

示例：

osprey -i sample.mzML -l library.tsv -o results.blib

osprey -i *.mzML -l library.tsv -o results.blib --resolution hram

HPC 拆分（一个节点 = 一个“--task”）：请参见上方的“--task”。

分布式执行（HPC）

不指定 --task 时，整个流程在一个进程中运行。对于分布式（HPC／工作流引擎）执行，流程在合并／扇出边界处拆分为四个单任务工作进程，每个节点对应一个 --task：PerFileScoring（拆分，每个文件）→ FirstPassFDR（合并，所有文件）→ PerFileRescoring（拆分，每个文件）→ SecondPassFDR（合并，所有文件）。请向每个任务传入相同的 --library 和搜索选项；parquet 完整性检查会拒绝搜索／库哈希不匹配的输入。

# 拆分 1 - 每个 mzML 一个进程（在每个输入旁写入 <stem>.scores.parquet、<stem>.calibration.json）
Osprey --task PerFileScoring -i s1.mzML -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01

# 合并 1 - 对所有运行使用一个进程（传入排序后的列表，以确保顺序确定）
Osprey --task FirstPassFDR --input-list runs.txt -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01
#   在每个 parquet 旁写入：<stem>.1st-pass.fdr_scores.bin、<stem>.reconciliation.json

# 拆分 2 - 每个文件一个进程（得分 parquet 及其中间文件一起）
Osprey --task PerFileRescoring -i s1.mzML -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01
#   写入：<stem>.scores-reconciled.parquet，使用“--training-export”时还写入 <stem>.training.parquet

# 合并 2 - 对所有运行使用一个进程，读取协调后的 parquet（写入 out.blib）
Osprey --task SecondPassFDR --input-list runs.txt -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01

每个任务都要用 -i 指定数据文件，名称与第一次拆分时相同。合并任务根据输入文件名主干推导每次运行的 parquet 和中间文件，因此数据文件本身不必仍然存在：工作进程的工作目录（或 --output-dir 下）中必须有该运行的产物。FirstPassFDR 协调对顺序敏感，因此请传入确定排序的列表。--input-list 每行接受一个路径；由于 -i 占用的命令行长度与文件数成正比，运行数超过几百个的队列需要使用它。请让调度程序进行扇出（每个拆分进程一个文件），而不要使用 --parallel-files，它是单节点多文件模式。
