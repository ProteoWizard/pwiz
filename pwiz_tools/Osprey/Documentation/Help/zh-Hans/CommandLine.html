Osprey 命令行用法

Osprey 是 MacCoss 实验室开发的以肽段为中心的 DIA 搜索工具。它读取 DIA mzML 文件和谱图库，并将经过 FDR 控制的结果写入 BiblioSpecLite（.blib）库，该库可直接导入 Skyline。它在 Windows 和 Linux 上作为独立的可执行文件运行。

有关流程概述、各阶段详情以及四个分布式 HPC 任务如何拆分与合并，请参见工作流程图：Osprey-workflow.html。下方的参数表由命令行声明生成，因此始终与构建版本一致；运行 Osprey --help 可查看相同内容的文本版本。

Osprey - 以肽段为中心的 DIA 分析

用法：Osprey -i 路径/到/文件 ... -l 路径/到/文件.blib|.tsv -o 路径/到/文件.blib

Osprey -i 路径/到/文件 ... --fasta 路径/到/文件.fasta -o 路径/到/文件.blib

一般输入/输出
参数描述
-i, --input 路径/到/文件 ...Mass spectrometry data files to search: mzML, or any format ProteoWizard reads, including vendor files (.raw, .d, .wiff, .lcd) where the vendor readers are installed
--input-list 路径/到/文件.txt输入路径列表文件，每行一个（忽略 # 注释）。可替代很长的“-i”列表。
-l, --library 路径/到/文件.blib|.tsvSpectral library to search: a .blib (as --fasta and CarafeSharp write it, or one from Skyline or BiblioSpec), or, for comparing with DIA-NN, a library in the .tsv format DIA-NN imports, such as Java Carafe writes for it. Without --decoys-in-library, Osprey generates a reversed decoy for every target, and a library that holds decoys is refused. With --decoys-in-library, the library's own decoys are used: a .blib pairs them from its own table, and a .tsv marks them by its Decoy column or a decoy accession prefix and pairs them by --decoy-pairing-manifest (an FDRBench pairing manifest) or by composition.
-o, --output 路径/到/文件.blibThe search result, for Skyline: a .blib that holds, for every precursor that passes FDR, the library spectrum it was searched with (the predicted one, with --fasta), the retention time and peak boundaries of its best run, its experiment-wide precursor q-value and PEP and its peptide q-value, and, for every run it was detected in, that run's retention time, peak boundaries and q-value. The protein groups its peptides belong to are in it too, with their q-values.
--work-dir 路径/到/文件夹Write the intermediate files and the caches here instead of beside each input, so the data folder can be read-only. --output-dir and --cache-dir send one of the two elsewhere.
--output-dir 路径/到/文件夹Write the intermediate files here - each run's scores and calibration and the analysis-wide FDR files - overriding --work-dir. The output and its reports stay where -o names.
--cache-dir 路径/到/文件夹Where Osprey keeps the files it builds once and reuses in later searches: each run's .spectra.bin (its spectra, faster to read than the data file) and, for a .tsv library, the .blib it is converted to (e.g. hela.tsv.blib). By default each goes beside the file it comes from, or under --output-dir or --work-dir when that folder is read-only. Give it to put them elsewhere, for example when the data and the library are on a read-only share, or to let several analyses share one cache. An HPC run (--task) that writes to an --output-dir away from the data should give every node the same one.
--export-library 路径/到/文件.blibWrite the library given by --library to this path as a .blib and exit without searching. It is the file a search keeps in its cache for a .tsv library (e.g. hela.tsv.blib): the library as a search loads it, with its decoys and their pairing in its own table (with --decoys-in-library, and --decoy-pairing-manifest for a .tsv), so it needs no manifest, searches back exactly as the original did, and Skyline can import it.
Library Build
参数描述
--fasta 路径/到/文件.fastaPredict the spectral library from this protein FASTA with CarafeSharp's models and search it, in place of -l. The library is written beside the output as <output>.predicted.blib and can be given to -l next time; its working files go in <output>.predicted/. The options of the Library Digest and Library Prediction sections apply, and with --training-input those of Library Tuning.
--precursors 路径/到/文件.tsvWith --task PredictLibrary and -o: predict a spectral library for exactly the precursors of this tab-separated table (columns sequence, mods, mod_sites, charge, in alphabase's notation, as Skyline writes it for its Build Library) and write it beside the output as <output>.predicted.speclib.tsv, the TSV peptdeep writes. The pretrained models or --model predict; the Library Prediction options apply, the Library Digest options and the entrapment do not. With --training-input and --fasta, the FASTA is the training library the tuning runs are searched against, the models are tuned on them first, and the tuned models predict the table; --task PredictLibrary is then not needed, and the Library Digest and Library Tuning options apply to the training library.
--training-input 路径/到/文件 ...With --fasta: tune the models on these runs before the library is predicted. The runs are searched with a library predicted as it is without this option, their training exports tune the MS2 and RT models, and the library the output is searched with is predicted with the tuned models. A run need not be one of -i: one that is not is searched for the tuning only and is absent from the output. The tuned model is saved beside the output as <output>.model.zip, which --model takes next time. The options of the Library Tuning section apply.
--training-input-list 路径/到/文件.txtWith --fasta: a file of --training-input runs, one path per line (# comments ignored), as --input-list is for -i: a long list of runs on the command line can pass the Windows command-line limit and hides the other arguments.
--model 路径/到/文件.model.zipWith --fasta: predict the library with this saved fine-tuned model (.model.zip, from CarafeSharp's training) instead of the pretrained models. With --training-input, the tuning starts from it.
--device <auto | gpu | cpu>With --fasta: where the library is predicted, auto (default: the GPU when this computer has an NVIDIA GPU that can use the CUDA runtime and the runtime is installed, see --install-cuda-runtime, else the CPU), gpu (the GPU; a run that cannot use it fails before it starts, saying why) or cpu. The log names the device every library phase ran on.
--torch-runtimes 路径/到/文件夹The folder of installed libtorch runtimes, where --install-cuda-runtime installs the NVIDIA CUDA runtime and --device looks for it, each runtime in a folder of its own (default: Osprey\torch under the user's local application data folder). Skyline passes its Tools folder, so one download serves its AlphaPeptDeep and Osprey; a cluster job names a shared folder.
--install-cuda-runtimeDownload the NVIDIA CUDA runtime from nuget.org (several GB; the size is logged first, and every package is checked against the hashes this build was tested with) into the --torch-runtimes folder and exit, so that --device can predict on the GPU. Needs nothing else on the command line.
--entrapment [<ratio>]With --fasta: add an entrapment peptide to every target (or to this fraction of the targets, 0.1 to 1), shuffled from the target or, with --entrapment-fasta, drawn from a foreign proteome, each with a decoy of its own. For measuring the true FDR with FDRBench, whose pairing manifest is written as <output>.predicted/pairing.tsv.
--entrapment-fasta 路径/到/文件.fastaWith --entrapment: draw the entrapment peptides, matched in mass, from this foreign-species protein FASTA instead of shuffling the targets.

Library Prediction

With --fasta: how the library is predicted. These are CarafeSharp's options, under their standard names.

参数描述
--lf-frag-mz-min <mz>Minimum fragment m/z (default 200).
--lf-frag-mz-max <mz>Maximum fragment m/z (default 1800).
--lf-top-n-frag <n>Fragments kept per precursor, the most intense first (default 20).
--lf-min-n-frag <n>Minimum fragments for a precursor to be written (default 2).
--lf-frag-n-min <n>Lowest fragment ordinal kept, b and y alike (default 2).
--nce <nce>The normalized collision energy the MS2 model predicts at (default 27, or the one the fine-tuned model it predicts with was trained at).
--ms-instrument <QE | QE+ | QEHF | QEHFX | Exploris | Exploris480 | Lumos | Fusion | Eclipse | Astral | Stellar | Velos | Elite | OrbitrapTribrid | ThermoTribrid | TribridOT | timsTOF | SciexTOF | ThermoTOF>The instrument the fragment intensities are predicted for (default Eclipse, or the one a fine-tuned model was trained on). Each name selects one of the five instrument groups the pretrained model knows: QE (QE, QE+, QEHF, QEHFX, Exploris), Lumos (Lumos, Fusion, Eclipse, Astral, Stellar, Velos, Elite, the Tribrids), timsTOF, SciexTOF and ThermoTOF.
--activation <beam-CID | reCID>The fragmentation the library is predicted for: beam-CID (HCD, and Sciex's and Bruker's CID) or reCID (resonance CID in an ion trap). Not given, the one a fine-tuned model was trained on.
--analyzer <Orbitrap | LIT | ToF>The MS2 mass analyzer the library is predicted for: Orbitrap, LIT (a linear ion trap, as a Stellar's) or ToF (an Astral's, a timsTOF's, a Sciex TOF's). Not given, the one a fine-tuned model was trained on.
--rt-max <minutes>The gradient length the library's retention times are scaled to, in minutes; absent, iRT.
--ccsPredict ion mobility (1/K0) for timsTOF.
--rt-model <alphapeptdeep | chronologer>The retention-time model (default: the fine-tuned model's, else chronologer). A different one from a fine-tuned model's predicts with its pretrained model, Chronologer's in iRT. Not in Java Carafe.
--pretrained path/to/file.zipThe AlphaPeptDeep pretrained models zip (default: the one beside the executable).
Library Tuning

With --training-input: how the models are tuned on its runs. These are CarafeSharp's options, under their standard names.

参数描述
--tf <all | ms2 | rt>The models to train: all (default), ms2 or rt.
--cor <r>The minimum fragment correlation of a precursor trained on (default 0.75).
--n-ion-min <n>The lowest b-ion ordinal trained on (default 0, every ordinal).
--c-ion-min <n>The lowest y-ion ordinal trained on (default 0, every ordinal).
--nf <n>The minimum matched fragments of a precursor trained on (default 4).
--min-n <n>The minimum valid fragments of a precursor trained on (default 4).
--validRequire a precursor's most intense fragment to be valid.
--no-maskingTrain on every ion of the kept spectra, masking none.
--seed <n>The random seed of training (default 2024; not negative).
--rt-align <none | kde>How the training runs' retention times are aligned before the RT model is fine-tuned: kde (default; each run's minutes mapped onto Chronologer's hydrophobic index by a KDE ridge on 1000 peptide forms or more, else a LOESS or a line; runs on one gradient train a model of their aligned minutes, runs on different gradients a Chronologer of the index) or none (Carafe's one rt_max). Not in Java Carafe.
--rt-select <best | median>With aligned runs, the retention time a peptide form trains on: its best run, or the runs' median.
--rt-reference <run>With a model trained with --rt-align kde, the training run whose minutes the library takes; else the model's, and iRT for a model of runs on different gradients. Not in Java Carafe.
评分与耐受性
参数描述
--resolution <hram | unit>How spectra are scored: hram (the default; Orbitrap, Astral and TOF instruments) bins them finely, uses the MS1 precursor features, and matches fragments and precursors within 10 ppm; unit (ion traps such as Stellar) bins them coarsely, without MS1 features, and matches fragments within 0.5 m/z and precursors within 1.0 m/z. The resolution is not detected from the data: a search of unit-resolution data must give unit.
--fragment-tolerance <数>The fragment m/z tolerance, in the unit --fragment-unit names (default: 10 ppm, or 0.5 m/z with --resolution unit).
--fragment-unit <ppm | mz>The unit of --fragment-tolerance: ppm or mz (default: ppm, or mz with --resolution unit).
--no-prefilterScore every library precursor in each isolation window, not only those whose fragments first show a coelution signal. About 30% slower; for checking that the pre-filter loses no detections.
--demux <off | auto>Demultiplex overlapping-window (staggered) DIA to its narrow bins before searching (default: off)
FDR 与蛋白质推断
参数描述
--run-fdr <threshold>The run-level FDR threshold (default: 0.01). A reported precursor gets an identification in Skyline in each run where its q-value in that run is at most this, or in its best run when it is in none; the scoring model is also trained and tested at it.
--experiment-fdr <threshold>The experiment-level FDR threshold (default: 0.01): a precursor is reported when its q-value across all the runs is at most this. --fdr-level says which q-value.
--reconciliation-compaction-fdr <threshold>为跨运行协调和第二轮保留第一轮肽段的肽段 q 值阈值（默认：0.01 =“--run-fdr”；可放宽，例如到 0.05，以扩大协调池）
--protein-fdr <threshold>Protein-level FDR threshold (default: 0.01)
--fdr-level <precursor | peptide | both>Which experiment-level q-value --experiment-fdr applies to: precursor (the default; each precursor's own), peptide (its peptide's, over all its charge states), or both (the larger of the two).
--shared-peptides <all | razor | unique>How a peptide shared by several protein groups counts in protein inference: all (the default; toward every group it maps to), razor (toward only the group with the most unique peptides), or unique (toward none).
--fdrbench 路径/到/文件.tsv将与 FDRBench 兼容的输入 TSV 写入此路径。水平取自“--fdr-level”（peptide；precursor 和 both 输出母离子水平）。包含每个报告的目标，即实际写入输出的肽段，不论 q 值如何，并将原始 SVM 判别值作为“score”，以便 FDRBench 通过诱捕计数计算真实 FDR，而不会在 Osprey 的阈值处截断。
--fdrbench-per-run与“--fdrbench”一起使用：每个（母离子，运行）输出一行，使用运行水平 q 值（增加“run”列）。默认每个母离子输出一行，使用实验水平 q 值。
--fdrbench-pass <1 | 2 | both>与“--fdrbench”一起使用：要输出哪一轮 FDR。2（默认）= 写入 blib 的第二轮结果（即 Osprey 所报告内容的 FDR）。1 = 为第二轮筛选之前的完整第一轮池（每个已评分目标，不论 q 值），使用第一轮 q 值，与原始 Rust Osprey 的 FDRBench 输入一致（第二轮输出所依据的假设）。both = 在一次运行中同时输出两者，写入“--fdrbench”路径时使用 .pass1 / .pass2 文件名后缀。
诱饵
参数描述
--decoys-in-librarySearch with the decoys the library holds instead of generating a reversed decoy for every target. A decoy is recognized by the library's own decoy table (in a .blib), by its Decoy column (in a .tsv), or by a protein accession starting with one of DECOY_, rev_, decoy_; the search stops with an error when none is recognized.
--decoy-pairing-manifest 路径/到/文件.tsvWith --decoys-in-library and a .tsv library: the FDRBench pairing manifest (a 5-column TSV) that pairs each decoy, and each entrapment peptide, with its target. A .blib library carries its pairing in its own table and needs none.

--training-export-max-q <q>With --training-export: the run precursor q-value a target must reach to be exported (default: --run-fdr)

性能
参数描述
--threads <整数>每个文件的主搜索线程数（内层；默认：所有核心），在“--parallel-files”同时运行的文件之间分配
--parallel-files [<N>]Input files run concurrently by each per-file stage (OUTER) that has no flag of its own below. Absent: one at a time (default). No value: auto from free RAM and cores. <N>: exactly N regardless of RAM/cores. Distinct from --threads. --parallel-files-rescoring [<N>]Files re-scored concurrently (PerFileRescoring, and the second-pass per-file phases), overriding --parallel-files for that stage only, in the same forms.
分布式 / HPC

--fasta runs as one process, or task by task: --task PredictTrainingLibrary; the four search stages with --training-search; --task TrainModel; --task PredictLibrary; then the four search stages. Every node takes the same command line and its own --task, and each task reads only what the tasks before it wrote.

参数描述
--task <SpectraCache | PredictTrainingLibrary | TrainModel | PredictLibrary | PerFileScoring | FirstPassFDR | PerFileRescoring | SecondPassFDR | TrainingExport | ModelDiagnostics>HPC: run exactly one task (one node = one task). Omit for the full pipeline. SpectraCache stages the .spectra.bin caches; TrainingExport writes the --training-export parquets, and on a COMPLETED run only the missing ones; ModelDiagnostics regenerates only the --model-diagnostics report for a COMPLETED run, writing no other output. With --fasta, PredictTrainingLibrary, TrainModel and PredictLibrary run the library build one phase at a time, and the four search stages search the library it predicts, or with --training-search the tuning runs.
--training-searchWith --fasta and --training-input: the stage --task selects is a stage of the tuning runs' search, not the output's: it searches the --training-input runs with the library PredictTrainingLibrary predicts, writes into <output>.predicted/training/, and writes the training exports TrainModel reads. Give it to every node of that search and the same command line without it to the others. The same four tasks for any number of tuning runs, one included.
--task-filesWith --task: print the files the task reads and writes for this command line, one per line as input or output, the task and the path, and exit without running it: what a node must be given and what it hands on.

Osprey -i *.raw --fasta human.fasta -o results.blib

Osprey -i *.raw --fasta human.fasta --training-input-list tuning.txt -o results.blib

Osprey -i *.raw -l results.predicted.blib -o results2.blib

Osprey -i *.mzML -l library.blib -o results.blib --resolution unit

Osprey -i *.d -l library.blib -o results.blib

Osprey -i *.mzML -l diann_library.tsv -o results.blib

HPC 拆分（一个节点 = 一个“--task”）：请参见上方的“--task”。

也接受的其他形式：值也可以用“=”连在选项后（--output=results.blib）；已存在的文件可以不带 -i 直接给出。 The library build options are listed in the standard form (--miss-c 1) and, for compatibility with Java Carafe's command lines, also accepted as Carafe spells them, with underscores or in camel case (--miss_c 1, --minLength 7).

分布式执行（HPC）

不指定 --task 时，整个流程在一个进程中运行。对于分布式（HPC／工作流引擎）执行，流程在合并／扇出边界处拆分为四个单任务工作进程，每个节点对应一个 --task：PerFileScoring（拆分，每个文件）→ FirstPassFDR（合并，所有文件）→ PerFileRescoring（拆分，每个文件）→ SecondPassFDR（合并，所有文件）。请向每个任务传入相同的 --library 和搜索选项；parquet 完整性检查会拒绝搜索／库哈希不匹配的输入。

# 拆分 1 - 每个 mzML 一个进程（在每个输入旁写入 <stem>.scores.parquet、<stem>.calibration.json）
Osprey --task PerFileScoring -i s1.mzML -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01

# 合并 1 - 对所有运行使用一个进程（传入排序后的列表，以确保顺序确定）
Osprey --task FirstPassFDR --input-list runs.txt -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01
#   在每个 parquet 旁写入：<stem>.1st-pass.fdr_scores.bin、out.1st-pass.*

# 拆分 2 - 每个文件一个进程（得分 parquet 及其中间文件一起）
Osprey --task PerFileRescoring -i s1.mzML -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01
#   写入：<stem>.scores-reconciled.parquet，使用“--training-export”时还写入 <stem>.training.parquet

# 合并 2 - 对所有运行使用一个进程，读取协调后的 parquet（写入 out.blib）
Osprey --task SecondPassFDR --input-list runs.txt -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01

每个任务都要用 -i 指定数据文件，名称与第一次拆分时相同。合并任务根据输入文件名主干推导每次运行的 parquet 和中间文件，因此数据文件本身不必仍然存在：工作进程的工作目录（或 --output-dir 下）中必须有该运行的产物。FirstPassFDR 协调对顺序敏感，因此请传入确定排序的列表。--input-list 每行接受一个路径；由于 -i 占用的命令行长度与文件数成正比，运行数超过几百个的队列需要使用它。请让调度程序进行扇出（每个拆分进程一个文件），而不要使用 --parallel-files，它是单节点多文件模式。
