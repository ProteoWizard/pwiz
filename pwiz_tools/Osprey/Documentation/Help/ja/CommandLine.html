Ospreyコマンドラインの使用法

Ospreyは、MacCossラボによるペプチド中心型のDIA検索ツールです。DIA mzMLファイルとスペクトルライブラリを読み込み、FDR制御された結果をBiblioSpecLite（.blib）ライブラリとして書き込みます。このライブラリはSkylineに直接インポートできます。WindowsとLinuxでスタンドアロンの実行ファイルとして動作します。

パイプラインの概要、各段階の詳細、および4つの分散HPCタスクの分割と結合については、ワークフロー図Osprey-workflow.htmlを参照してください。以下の引数表はコマンドラインの宣言から生成されるため、常にビルドと一致します。同じ内容をテキストで表示するには、Osprey --helpを実行してください。

Osprey - ペプチド中心のDIA解析

使用法：Osprey -i path/to/file（ファイル） ... -l path/to/file（ファイル）.blib|.tsv -o path/to/file（ファイル）.blib

Osprey -i path/to/file（ファイル） ... --fasta path/to/file（ファイル）.fasta -o path/to/file（ファイル）.blib

一般I/O
引数説明
-i, --input path/to/file（ファイル） ...Mass spectrometry data files to search: mzML, or any format ProteoWizard reads, including vendor files (.raw, .d, .wiff, .lcd) where the vendor readers are installed
--input-list path/to/file（ファイル）.txt入力パスを記載したファイル（1行に1つ、#コメントは無視）。長い-iリストの代わりに使用できます。
-l, --library path/to/file（ファイル）.blib|.tsvSpectral library to search: a .blib (as --fasta and CarafeSharp write it, or one from Skyline or BiblioSpec), or, for comparing with DIA-NN, a library in the .tsv format DIA-NN imports, such as Java Carafe writes for it. Without --decoys-in-library, Osprey generates a reversed decoy for every target, and a library that holds decoys is refused. With --decoys-in-library, the library's own decoys are used: a .blib pairs them from its own table, and a .tsv marks them by its Decoy column or a decoy accession prefix and pairs them by --decoy-pairing-manifest (an FDRBench pairing manifest) or by composition.
-o, --output path/to/file（ファイル）.blibThe search result, for Skyline: a .blib that holds, for every precursor that passes FDR, the library spectrum it was searched with (the predicted one, with --fasta), the retention time and peak boundaries of its best run, its experiment-wide precursor q-value and PEP and its peptide q-value, and, for every run it was detected in, that run's retention time, peak boundaries and q-value. The protein groups its peptides belong to are in it too, with their q-values.
--work-dir path/to/folder（フォルダ）Write the intermediate files and the caches here instead of beside each input, so the data folder can be read-only. --output-dir and --cache-dir send one of the two elsewhere.
--output-dir path/to/folder（フォルダ）Write the intermediate files here - each run's scores and calibration and the analysis-wide FDR files - overriding --work-dir. The output and its reports stay where -o names.
--cache-dir path/to/folder（フォルダ）Where Osprey keeps the files it builds once and reuses in later searches: each run's .spectra.bin (its spectra, faster to read than the data file) and, for a .tsv library, the .blib it is converted to (e.g. hela.tsv.blib). By default each goes beside the file it comes from, or under --output-dir or --work-dir when that folder is read-only. Give it to put them elsewhere, for example when the data and the library are on a read-only share, or to let several analyses share one cache. An HPC run (--task) that writes to an --output-dir away from the data should give every node the same one.
--export-library path/to/file（ファイル）.blibWrite the library given by --library to this path as a .blib and exit without searching. It is the file a search keeps in its cache for a .tsv library (e.g. hela.tsv.blib): the library as a search loads it, with its decoys and their pairing in its own table (with --decoys-in-library, and --decoy-pairing-manifest for a .tsv), so it needs no manifest, searches back exactly as the original did, and Skyline can import it.
Library Build
引数説明
--fasta path/to/file（ファイル）.fastaPredict the spectral library from this protein FASTA with CarafeSharp's models and search it, in place of -l. The library is written beside the output as <output>.predicted.blib and can be given to -l next time; its working files go in <output>.predicted/. The options of the Library Digest and Library Prediction sections apply, and with --training-input those of Library Tuning.
--training-input path/to/file（ファイル） ...With --fasta: tune the models on these runs before the library is predicted. The runs are searched with a library predicted as it is without this option, their training exports tune the MS2 and RT models, and the library the output is searched with is predicted with the tuned models. A run need not be one of -i: one that is not is searched for the tuning only and is absent from the output. The tuned model is saved beside the output as <output>.model.zip, which --model takes next time. The options of the Library Tuning section apply.
--training-input-list path/to/file（ファイル）.txtWith --fasta: a file of --training-input runs, one path per line (# comments ignored), as --input-list is for -i: a long list of runs on the command line can pass the Windows command-line limit and hides the other arguments.
--model path/to/file（ファイル）.model.zipWith --fasta: predict the library with this saved fine-tuned model (.model.zip, from CarafeSharp's training) instead of the pretrained models. With --training-input, the tuning starts from it.
--device <auto | gpu | cpu>With --fasta: where the library is predicted, auto (default: the GPU when this computer has an NVIDIA GPU that can use the CUDA runtime and the runtime is installed, see --install-cuda-runtime, else the CPU), gpu (the GPU; a run that cannot use it fails before it starts, saying why) or cpu. The log names the device every library phase ran on.
--torch-runtimes path/to/folder（フォルダ）The folder of installed libtorch runtimes, where --install-cuda-runtime installs the NVIDIA CUDA runtime and --device looks for it, each runtime in a folder of its own (default: Osprey\torch under the user's local application data folder). Skyline passes its Tools folder, so one download serves its AlphaPeptDeep and Osprey; a cluster job names a shared folder.
--install-cuda-runtimeDownload the NVIDIA CUDA runtime from nuget.org (several GB; the size is logged first, and every package is checked against the hashes this build was tested with) into the --torch-runtimes folder and exit, so that --device can predict on the GPU. Needs nothing else on the command line.
--entrapment [<ratio>]With --fasta: add an entrapment peptide to every target (or to this fraction of the targets, 0.1 to 1), shuffled from the target or, with --entrapment-fasta, drawn from a foreign proteome, each with a decoy of its own. For measuring the true FDR with FDRBench, whose pairing manifest is written as <output>.predicted/pairing.tsv.
--entrapment-fasta path/to/file（ファイル）.fastaWith --entrapment: draw the entrapment peptides, matched in mass, from this foreign-species protein FASTA instead of shuffling the targets.

--lf-frag-mz-max <mz>Maximum fragment m/z (default 1800).

Library Tuning

With --training-input: how the models are tuned on its runs. These are CarafeSharp's options, under their standard names.

引数説明
--tf <all | ms2 | rt>The models to train: all (default), ms2 or rt.
--cor <r>The minimum fragment correlation of a precursor trained on (default 0.75).
--n-ion-min <n>The lowest b-ion ordinal trained on (default 0, every ordinal).
--c-ion-min <n>The lowest y-ion ordinal trained on (default 0, every ordinal).
--nf <n>The minimum matched fragments of a precursor trained on (default 4).
--min-n <n>The minimum valid fragments of a precursor trained on (default 4).
--validRequire a precursor's most intense fragment to be valid.
--no-maskingTrain on every ion of the kept spectra, masking none.
--seed <n>The random seed of training (default 2024; not negative).
--rt-align <none | kde>How the training runs' retention times are aligned before the RT model is fine-tuned: kde (default; each run's minutes mapped onto Chronologer's hydrophobic index by a KDE ridge on 1000 peptide forms or more, else a LOESS or a line; runs on one gradient train a model of their aligned minutes, runs on different gradients a Chronologer of the index) or none (Carafe's one rt_max). Not in Java Carafe.
--rt-select <best | median>With aligned runs, the retention time a peptide form trains on: its best run, or the runs' median. Not in Java Carafe.
--rt-reference <run>With a model trained with --rt-align kde, the training run whose minutes the library takes; else the model's, and iRT for a model of runs on different gradients. Not in Java Carafe.
スコアリングと許容誤差
引数説明
--resolution <hram | unit>How spectra are scored: hram (the default; Orbitrap, Astral and TOF instruments) bins them finely, uses the MS1 precursor features, and matches fragments and precursors within 10 ppm; unit (ion traps such as Stellar) bins them coarsely, without MS1 features, and matches fragments within 0.5 m/z and precursors within 1.0 m/z. The resolution is not detected from the data: a search of unit-resolution data must give unit.
--fragment-tolerance <数字>The fragment m/z tolerance, in the unit --fragment-unit names (default: 10 ppm, or 0.5 m/z with --resolution unit).
--fragment-unit <ppm | mz>The unit of --fragment-tolerance: ppm or mz (default: ppm, or mz with --resolution unit).
--no-prefilterScore every library precursor in each isolation window, not only those whose fragments first show a coelution signal. About 30% slower; for checking that the pre-filter loses no detections.
--demux <off | auto>Demultiplex overlapping-window (staggered) DIA to its narrow bins before searching (default: off)
--centroid <vendor | centrix>Who centroids profile spectra: the vendor library, or Centrix, a lasso centroider for ion trap (unit resolution) profile data that separates peaks closer than 1 Th. Centrix reads the profile even from a vendor file, and its spectra are cached apart from the vendor-centroided ones (default: vendor)
--centrix-sigma-ms1 <Th>With --centroid centrix: the MS1 profile peak sigma in Th (default: 1.1 point spacings on a linear ion trap, otherwise one species' peak width measured from the run)
--centrix-sigma-ms2 <Th>With --centroid centrix: the MS2 profile peak sigma in Th (default: 1.1 point spacings on a linear ion trap, otherwise one species' peak width measured from the run)
--centrix-solver <descent | active-set>With --centroid centrix: how each region of a spectrum is fitted. descent: Centrix's own coordinate descent; active-set: the exact optimum of the same fit, several times faster (default: descent)
FDRとタンパク質推定
引数説明
--run-fdr <threshold>The run-level FDR threshold (default: 0.01). A reported precursor gets an identification in Skyline in each run where its q-value in that run is at most this, or in its best run when it is in none; the scoring model is also trained and tested at it.
--experiment-fdr <threshold>The experiment-level FDR threshold (default: 0.01): a precursor is reported when its q-value across all the runs is at most this. --fdr-level says which q-value.
--reconciliation-compaction-fdr <threshold>ラン間整合と第2パスのために第1パスのペプチドを保持する、ペプチドQ値閾値（デフォルト：0.01 = --run-fdr。整合のプールを広げるには、例えば0.05に緩めます）
--protein-fdr <threshold>Protein-level FDR threshold (default: 0.01)
--fdr-level <precursor | peptide | both>Which experiment-level q-value --experiment-fdr applies to: precursor (the default; each precursor's own), peptide (its peptide's, over all its charge states), or both (the larger of the two).
--shared-peptides <all | razor | unique>How a peptide shared by several protein groups counts in protein inference: all (the default; toward every group it maps to), razor (toward only the group with the most unique peptides), or unique (toward none).
--fdrbench path/to/file（ファイル）.tsvFDRBench互換の入力TSVをこのパスに書き込みます。レベルは--fdr-levelから取得します（peptide。precursorとbothはプリカーサーレベルを出力）。報告されたすべてのターゲット（つまり実際に出力に書き込まれたペプチド）をQ値に関係なく含み、生のSVM判別値を「score」として出力するため、FDRBenchはOspreyの閾値で切り捨てられることなく、エントラップメントのカウントによって真のFDRを計算できます。
--fdrbench-per-run--fdrbenchと併用：ランレベルのQ値を使用して（プリカーサー、ラン）ごとに1行を出力します（「run」列を追加）。デフォルトでは、実験レベルのQ値を使用してプリカーサーごとに1行を出力します。
--fdrbench-pass <1 | 2 | both>--fdrbenchと併用：出力するFDRパス。2（デフォルト）= blibに書き込まれる第2パスの結果（Ospreyが報告するもののFDR）。1 = 第2パス用にフィルタリングされる前の第1パスの全プール（Q値に関係なく、スコアリングされたすべてのターゲット）と第1パスのQ値で、元のRust版OspreyのFDRBench入力と一致します（第2パスの出力が前提とするもの）。both = 1回の実行で両方を出力し、--fdrbenchのパスに.pass1 / .pass2のステムサフィックスを付けて書き込みます。
デコイ
引数説明
--decoys-in-librarySearch with the decoys the library holds instead of generating a reversed decoy for every target. A decoy is recognized by the library's own decoy table (in a .blib), by its Decoy column (in a .tsv), or by a protein accession starting with one of DECOY_, rev_, decoy_; the search stops with an error when none is recognized.
--decoy-pairing-manifest path/to/file（ファイル）.tsvWith --decoys-in-library and a .tsv library: the FDRBench pairing manifest (a 5-column TSV) that pairs each decoy, and each entrapment peptide, with its target. A .blib library carries its pairing in its own table and needs none.

引数説明
--training-exportWrite <stem>.training.parquet per run: every target precursor at run q <= --training-export-max-q with the observed intensities of its full b/y ladder and per-ion interference evidence (for training CarafeSharp). Adding it to a finished run writes only the exports and re-scores nothing.
--training-export-max-q <q>With --training-export: the run precursor q-value a target must reach to be exported (default: --run-fdr)
--training-export-claimant-q <q>With --training-export: the run q-value at which another target counts as a claimant of a shared fragment peak (default: 0.01)
--training-export-xicsWith --training-export: also write each precursor's per-ion XIC matrix over its final peak boundaries
パフォーマンス
引数説明
--threads <整数>ファイルごとのメイン検索スレッド数（INNER。デフォルト：全コア）。--parallel-filesで並行実行されるファイル間で分割されます
--parallel-files [<N>]Input files run concurrently by each per-file stage (OUTER) that has no flag of its own below. Absent: one at a time (default). No value: auto from free RAM and cores. <N>: exactly N regardless of RAM/cores. Distinct from --threads. Worth setting only for high-resolution data on a server with more cores than one file's search can keep busy (a multi-socket, NUMA machine); on a workstation leave it unset and let --threads use the cores.
--parallel-files-caching [<N>]Files --task SpectraCache caches concurrently, overriding --parallel-files for that stage only, in the same forms (a full run caches inside scoring, at its count). A vendor decode runs on one thread, so this can exceed the scoring count; mzML parses still run one at a time.
--parallel-files-scoring [<N>]Files scored concurrently (PerFileScoring), overriding --parallel-files for that stage only, in the same forms.
--parallel-files-rescoring [<N>]Files re-scored concurrently (PerFileRescoring, and the second-pass per-file phases), overriding --parallel-files for that stage only, in the same forms.
分散 / HPC

--fasta runs as one process, or task by task: --task PredictTrainingLibrary; the four search stages with --training-search; --task TrainModel; --task PredictLibrary; then the four search stages. Every node takes the same command line and its own --task, and each task reads only what the tasks before it wrote.

引数説明
--task <SpectraCache | PredictTrainingLibrary | TrainModel | PredictLibrary | PerFileScoring | FirstPassFDR | PerFileRescoring | SecondPassFDR | TrainingExport | ModelDiagnostics>HPC: run exactly one task (one node = one task). Omit for the full pipeline. SpectraCache stages the .spectra.bin caches; TrainingExport writes the --training-export parquets, and on a COMPLETED run only the missing ones; ModelDiagnostics regenerates only the --model-diagnostics report for a COMPLETED run, writing no other output. With --fasta, PredictTrainingLibrary, TrainModel and PredictLibrary run the library build one phase at a time, and the four search stages search the library it predicts, or with --training-search the tuning runs.
--training-searchWith --fasta and --training-input: the stage --task selects is a stage of the tuning runs' search, not the output's: it searches the --training-input runs with the library PredictTrainingLibrary predicts, writes into <output>.predicted/training/, and writes the training exports TrainModel reads. Give it to every node of that search and the same command line without it to the others. The same four tasks for any number of tuning runs, one included.
--task-filesWith --task: print the files the task reads and writes for this command line, one per line as input or output, the task and the path, and exit without running it: what a node must be given and what it hands on.

例：

Osprey -i *.raw --fasta human.fasta -o results.blib

Osprey -i *.raw --fasta human.fasta --training-input-list tuning.txt -o results.blib

Osprey -i *.raw -l results.predicted.blib -o results2.blib

Osprey -i *.mzML -l library.blib -o results.blib --resolution unit

Osprey -i *.d -l library.blib -o results.blib

Osprey -i *.mzML -l diann_library.tsv -o results.blib

HPC分割（1ノード = 1つの--task）：上記の--taskを参照してください。

受け付けるその他の形式：値はオプションに「=」でつなげて指定することもでき（--output=results.blib）、存在するファイルは-iなしで指定できます。 The library build options are listed in the standard form (--miss-c 1) and, for compatibility with Java Carafe's command lines, also accepted as Carafe spells them, with underscores or in camel case (--miss_c 1, --minLength 7).

分散実行（HPC）

--taskを指定しない場合、パイプライン全体が1つのプロセスで実行されます。分散（HPC／ワークフローエンジン）実行では、パイプラインは結合／ファンアウトの境界で4つの単一タスクワーカーに分割されます（1ノード = 1つの--task）：PerFileScoring（分割、ファイルごと）→FirstPassFDR（結合、全ファイル）→PerFileRescoring（分割、ファイルごと）→SecondPassFDR（結合、全ファイル）。すべてのタスクに同じ--libraryと検索オプションを渡してください。parquetの整合性チェックにより、検索／ライブラリのハッシュが一致しない入力は拒否されます。

# 分割1 - mzMLごとに1プロセス（各入力の横に<stem>.scores.parquet、<stem>.calibration.jsonを書き込み）
Osprey --task PerFileScoring -i s1.mzML -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01

# 結合1 - 全ランに対して1プロセス（順序が決定的になるよう、ソート済みのリストを渡す）
Osprey --task FirstPassFDR --input-list runs.txt -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01
#   各parquetの横に書き込み：<stem>.1st-pass.fdr_scores.bin、out.1st-pass.*

# 分割2 - ファイルごとに1プロセス（スコアparquetとその中間ファイルをまとめて）
Osprey --task PerFileRescoring -i s1.mzML -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01
#   書き込み：<stem>.scores-reconciled.parquet、および--training-export指定時は<stem>.training.parquet

すべてのタスクに-iでデータファイルを指定します。名前は最初の分割で指定したものと同じです。結合タスクは各ランのparquetと中間ファイルを入力のステムから導き出すため、データファイル自体が残っている必要はありません。ワーカーの作業ディレクトリ（または--output-dirの下）に必要なのは、そのランの成果物です。FirstPassFDRの整合は順序に依存するため、決定的にソートされたリストを渡してください。--input-listは1行に1つのパスを受け取ります。-iではコマンドラインの長さがファイル数に比例して増えるため、数百ランを超えるコホートにはこちらが必要です。ファンアウトは--parallel-files（単一ノードでの複数ファイルモード）ではなく、スケジューラに任せてください（分割プロセスごとに1ファイル）。
