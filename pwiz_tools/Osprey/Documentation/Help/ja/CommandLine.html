Ospreyコマンドラインの使用法

Ospreyは、MacCossラボによるペプチド中心型のDIA検索ツールです。DIA mzMLファイルとスペクトルライブラリを読み込み、FDR制御された結果をBiblioSpecLite（.blib）ライブラリとして書き込みます。このライブラリはSkylineに直接インポートできます。WindowsとLinuxでスタンドアロンの実行ファイルとして動作します。

パイプラインの概要、各段階の詳細、および4つの分散HPCタスクの分割と結合については、ワークフロー図Osprey-workflow.htmlを参照してください。以下の引数表はコマンドラインの宣言から生成されるため、常にビルドと一致します。同じ内容をテキストで表示するには、Osprey --helpを実行してください。

Osprey - ペプチド中心のDIA解析

使用法：osprey -i <file1.mzML> [file2.mzML ...] -l <library.tsv> -o <output.blib>

一般I/O
引数説明
-i, --input <file1.mzML ...>入力mzMLファイル
--input-list <list.txt>入力パスを記載したファイル（1行に1つ、#コメントは無視）。長い-iリストの代わりに使用できます。
-l, --library <library.tsv|.blib>スペクトルライブラリ（.tsv、.blib）
-o, --output <output.blib>出力blibファイル
--work-dir <dir>中間ファイルとスペクトルキャッシュをここに書き込みます（入力データを読み取り専用にできます）。デフォルト：入力の横
--output-dir <dir>中間ファイルのディレクトリ（--work-dirより優先）
--cache-dir <dir>.spectra.binキャッシュのディレクトリ（--work-dirより優先）
--report <report.tsv>TSVレポートをファイルに書き込みます
--export-library <library.blib>Write the spectral library given by --library to this path as a .blib file that Skyline and Osprey can read, and exit without searching
スコアリングと許容誤差
引数説明
--resolution <unit | hram | auto>分解能モード（デフォルト：auto）
--fragment-tolerance <value>フラグメントm/z許容誤差（デフォルト：10）
--fragment-unit <ppm | mz>フラグメント許容誤差の単位（デフォルト：ppm）
--no-prefilter共溶出シグナルのプレフィルタを無効にします
FDRとタンパク質推定
引数説明
--run-fdr <threshold>ランレベルFDR閾値（デフォルト：0.01）
--experiment-fdr <threshold>実験レベルFDR閾値（デフォルト：0.01）
--reconciliation-compaction-fdr <threshold>ラン間整合と第2パスのために第1パスのペプチドを保持する、ペプチドQ値閾値（デフォルト：0.01 = --run-fdr。整合のプールを広げるには、例えば0.05に緩めます）
--protein-fdr <threshold>タンパク質レベルFDR閾値（オプション）
--fdr-level <precursor | peptide | both>FDRレベル（デフォルト：precursor）
--shared-peptides <all | razor | unique>共有ペプチドの処理（デフォルト：all）
--fdrbench <input.tsv>FDRBench互換の入力TSVをこのパスに書き込みます。レベルは--fdr-levelから取得します（peptide。precursorとbothはプリカーサーレベルを出力）。報告されたすべてのターゲット（つまり実際に出力に書き込まれたペプチド）をQ値に関係なく含み、生のSVM判別値を「score」として出力するため、FDRBenchはOspreyの閾値で切り捨てられることなく、エントラップメントのカウントによって真のFDRを計算できます。
--fdrbench-per-run--fdrbenchと併用：ランレベルのQ値を使用して（プリカーサー、ラン）ごとに1行を出力します（「run」列を追加）。デフォルトでは、実験レベルのQ値を使用してプリカーサーごとに1行を出力します。
--fdrbench-pass <1 | 2 | both>--fdrbenchと併用：出力するFDRパス。2（デフォルト）= blibに書き込まれる第2パスの結果（Ospreyが報告するもののFDR）。1 = 第2パス用にフィルタリングされる前の第1パスの全プール（Q値に関係なく、スコアリングされたすべてのターゲット）と第1パスのQ値で、元のRust版OspreyのFDRBench入力と一致します（第2パスの出力が前提とするもの）。both = 1回の実行で両方を出力し、--fdrbenchのパスに.pass1 / .pass2のステムサフィックスを付けて書き込みます。

例：

osprey -i sample.mzML -l library.tsv -o results.blib

osprey -i *.mzML -l library.tsv -o results.blib --resolution hram

HPC分割（1ノード = 1つの--task）：上記の--taskを参照してください。

分散実行（HPC）

--taskを指定しない場合、パイプライン全体が1つのプロセスで実行されます。分散（HPC／ワークフローエンジン）実行では、パイプラインは結合／ファンアウトの境界で4つの単一タスクワーカーに分割されます（1ノード = 1つの--task）：PerFileScoring（分割、ファイルごと）→FirstPassFDR（結合、全ファイル）→PerFileRescoring（分割、ファイルごと）→SecondPassFDR（結合、全ファイル）。すべてのタスクに同じ--libraryと検索オプションを渡してください。parquetの整合性チェックにより、検索／ライブラリのハッシュが一致しない入力は拒否されます。

# 分割1 - mzMLごとに1プロセス（各入力の横に<stem>.scores.parquet、<stem>.calibration.jsonを書き込み）
Osprey --task PerFileScoring -i s1.mzML -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01

# 結合1 - 全ランに対して1プロセス（順序が決定的になるよう、ソート済みのリストを渡す）
Osprey --task FirstPassFDR --input-list runs.txt -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01
#   各parquetの横に書き込み：<stem>.1st-pass.fdr_scores.bin、<stem>.reconciliation.json

# 分割2 - ファイルごとに1プロセス（スコアparquetとその中間ファイルをまとめて）
Osprey --task PerFileRescoring -i s1.mzML -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01
#   書き込み：<stem>.scores-reconciled.parquet、および--training-export指定時は<stem>.training.parquet

# 結合2 - 全ランに対して1プロセス、整合済みparquetを読み込み（out.blibを書き込み）
Osprey --task SecondPassFDR --input-list runs.txt -l hela.tsv -o out.blib --resolution unit --protein-fdr 0.01

すべてのタスクに-iでデータファイルを指定します。名前は最初の分割で指定したものと同じです。結合タスクは各ランのparquetと中間ファイルを入力のステムから導き出すため、データファイル自体が残っている必要はありません。ワーカーの作業ディレクトリ（または--output-dirの下）に必要なのは、そのランの成果物です。FirstPassFDRの整合は順序に依存するため、決定的にソートされたリストを渡してください。--input-listは1行に1つのパスを受け取ります。-iではコマンドラインの長さがファイル数に比例して増えるため、数百ランを超えるコホートにはこちらが必要です。ファンアウトは--parallel-files（単一ノードでの複数ファイルモード）ではなく、スケジューラに任せてください（分割プロセスごとに1ファイル）。
